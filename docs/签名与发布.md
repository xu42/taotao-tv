# Release 签名与发版

> 面向第一次接触 Android 的人。看完这一篇，你就能自己签出「能覆盖升级」的正式包。

## 一、为什么非要签名？

Android 靠**签名证书**来判断「这是不是同一个 App」：

- 同一个包名 `com.xu42.tv.live`，但**签名不同** → 系统认为是另一个 App，安装时报「应用未安装 / 签名不一致」，必须**先卸载**才能装。
- 签名相同 → 才能正常覆盖升级，用户数据（收藏、观看记录）保留。

所以：**签名密钥 = 这个 App 的身份，丢了就找不回来。**

### 现状（很重要）

仓库里那 4 个 Secrets 还没配，所以 CI 走的是 **debug 签名**回退分支。问题在于：

> GitHub 的每台构建机器都是全新的，`~/.android/debug.keystore` 不存在时会**现场随机生成一个**。

也就是说 —— **每次 CI 打出来的包，签名都不一样**。v1.0 装上了，下个版本装不上去，必须卸载重装。这是必须尽快配正式签名的真正原因。

---

## 二、三个概念

| 名词 | 是什么 | 例子 |
|---|---|---|
| **keystore**（密钥库） | 一个 `.jks` 文件，里面装着你的密钥对和证书 | `android/keystore/release.jks` |
| **alias**（别名） | 密钥库里的条目名，一个库可以放多个密钥 | `tao-tao-tv` |
| **password** | 密钥库密码 + 密钥密码，通常设成一样 | 自己起，≥6 位 |

生成后要记住「keystore 文件 + 别名 + 两个密码」这一组四件套，缺一不可。

## 三、动手：四步

### 第 1 步 — 生成密钥库

工程里已经准备好一键脚本（密码只在你终端里输入，不会经过任何网络）：

```bash
cd /Users/xu/work/me/taotao-tv
./android/scripts/gen-keystore.sh
```

它会问你别名、两次密码、几个证书署名信息，然后：

- 生成 `android/keystore/release.jks`
- 把 `RELEASE_STORE_FILE` / `RELEASE_STORE_PASSWORD` / `RELEASE_KEY_ALIAS` / `RELEASE_KEY_PASSWORD` 写进 `android/local.properties`
- 最后把 GitHub Secrets 需要的 **base64 字符串**打印出来

> 密钥库已经生成过、只是想再拿一次 base64（比如当时没存下来）：
> ```bash
> ./android/scripts/gen-keystore.sh --b64
> ```
> 它不会重新生成，只读现有的库把 Secrets 值再打一遍。

> `android/.gitignore` 已经忽略了 `/keystore/`、`*.jks`、`*.keystore`、`local.properties`，不会被提交。
>
> 不想用脚本也行，等价的手工命令：
> ```bash
> mkdir -p android/keystore
> keytool -genkeypair -keystore android/keystore/release.jks \
>   -alias tao-tao-tv -keyalg RSA -keysize 2048 -validity 10000 \
>   -dname "CN=taotao-tv, OU=dev, O=xu42, C=CN"
> ```
> 然后用编辑器把上面那 4 行 `RELEASE_*` 写进 `android/local.properties`。
> ⚠️ `RELEASE_STORE_FILE` 要写 `../keystore/release.jks`（相对 `android/app/` 解析），漏掉 `../` 会找不到文件、静默退回 debug 签名。

### 第 2 步 — 本地验证

```bash
cd android
./gradlew clean assembleRelease

# 看签名到底是谁
"$(ls $HOME/Library/Android/sdk/build-tools/*/apksigner | tail -1)" verify --print-certs \
  "$(ls -t app/build/outputs/apk/release/*.apk | head -1)"
```

- ✅ 看到 `CN=taotao-tv`（你填的名字）→ 正式签名生效
- ❌ 看到 `CN=Android Debug` → 还是回退了，检查 `local.properties` 的 4 行是否写对、`.jks` 路径是否存在

### 第 3 步 — 传到 GitHub Secrets

打开 <https://github.com/xu42/taotao-tv/settings/secrets/actions> → **New repository secret**，加这 4 个（名字必须一字不差）：

| Secret 名称 | 值 |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | 脚本最后打印的那一长串 base64（**要一整行**，别换行、别加空格） |
| `RELEASE_STORE_PASSWORD` | 你的密钥库密码 |
| `RELEASE_KEY_ALIAS` | 你的别名 |
| `RELEASE_KEY_PASSWORD` | 你的密钥密码 |

也可以命令行加（需要先 `brew install gh` 并 `gh auth login`）：

```bash
base64 -i android/keystore/release.jks | tr -d '\n' | gh secret set RELEASE_KEYSTORE_BASE64
gh secret set RELEASE_STORE_PASSWORD
gh secret set RELEASE_KEY_ALIAS
gh secret set RELEASE_KEY_PASSWORD
```

CI 侧的逻辑（`.github/workflows/build-apk.yml` 的「准备签名密钥」步骤）：

- Secret 存在 → 解 base64 写到 `android/keystore/release.jks`，并生成 `android/local.properties` → **正式签名**
- Secret 不存在 → 打印警告，回退 debug 签名（产物仍可安装，但不能覆盖升级）

### 第 4 步 — 打 tag 发版

```bash
git tag -a v1.0.1 -m "修了 xxx"
git push origin v1.0.1
```

流水线只在**推 tag** 时触发，会自动编译并挂到该 tag 的 Release 上。

## 四、⚠️ 备份（比前面所有步骤都重要）

**必须**在生成后立刻另存一份到仓库之外：

```bash
cp -r android/keystore ~/Documents/taotao-tv-keystore-backup-$(date +%Y%m%d)
```

建议同时放进密码管理器（1Password / Bitwarden / KeePass），把 **keystore 文件 + 别名 + 两个密码** 一起存。

丢了会怎样：

- 已经装过正式签名版本的用户，**永远**没法再收到你的升级，只能卸载重装（收藏、观看记录一起清空）。
- Google Play / 各应用商店的已发布应用**无法更新**。
- 没有任何官方途径能找回或重置。

也不要提交到 git、不要发群、不要贴 issue。真要给别人，走加密渠道。

## 五、常见问题

**Q：已经发布的 v1.0 怎么办？**
它是 debug 签名（而且每次构建都不同），和正式签名不兼容。配好密钥后，用户需要**卸载旧版再装新版**。建议在 Release 说明里写一句，或者干脆把 v1.0 标注为内测包。

**Q：换了新密钥库会怎样？**
同上，等于换了个 App 身份。所以密钥库要「一次生成、终身使用」。

**Q：`local.properties` 会不会被提交？**
不会。根 `.gitignore` 和 `android/.gitignore` 都忽略了它，而且里面还有 `sdk.dir`，本来就是本机专属文件。

**Q：密码想改怎么办？**
`keytool -storepasswd -keystore release.jks` 改库密码，`keytool -keypasswd -keystore release.jks -alias <别名>` 改密钥密码。改完记得同步更新 `local.properties` 和 GitHub Secrets。

**Q：有效期 10000 天到了怎么办？**
≈27 年后的事。真要延期用 `keytool -selfcert`。证书过期不影响已发布的 App 继续运行。

**Q：跑脚本时报 `unbound variable` 中途退出，密钥库生成了吗？**
多半生成了——这类报错发生在最后的打印环节。去看 `android/keystore/release.jks` 在不在、`local.properties` 里 4 行 `RELEASE_*` 齐不齐，然后用 `./android/scripts/gen-keystore.sh --b64` 把 base64 补打出来即可。

> 背后的坑（自己写 shell 脚本时注意）：在 UTF-8 环境下 bash 会把**中文全角标点**当成变量名的一部分。
> `echo "$VAR（说明）"` 会去找一个叫 `VAR（` 的变量，配上 `set -u` 就直接报错退出。
> 写脚本时变量一律用 `${VAR}` 花括号包起来，紧跟中文也别怕。
